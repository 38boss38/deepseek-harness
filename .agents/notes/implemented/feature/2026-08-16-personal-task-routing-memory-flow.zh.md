# Agent Note: 个人任务路由、行动手册与记忆流

Status: implemented

[English](2026-08-16-personal-task-routing-memory-flow.md) | 中文

## 问题

个人 Harness 需要稳定的任务身份、路由专属执行纪律与可复用记忆，同时不能把核心 agent loop（智能体循环）变成用户专属策略引擎。纯提示词指令无法提供确定性路由、完整分类覆盖、持久来源信息、任务隔离或删除能力；不可见上下文则会让模型行为依赖会话日志中不存在的数据。

## 决策

个人路由、行动手册与记忆以三个上下文包加一个组合包交付。[`dsh-task-router`](../../../../packages/context/task-router/README.md) 根据最新一条人类直接消息选择一个已配置任务，并在第一个步骤记录带版本的路由快照。[`dsh-task-playbook`](../../../../packages/context/task-playbook/README.md) 要求每条已配置路由恰好对应一份有界行动手册，并记录所选目标、工作流、完成检查与注意事项。[`dsh-memory-flow`](../../../../packages/context/memory-flow/README.md) 消费 `ctx.taskRouter`，把显式模型工具捕获存入 storage-domain 表，仅检索全局条目和属于所选任务的条目，并把确切的有界召回记录成带版本的会话消息。[`dsh-personal-harness`](../../../../packages/bundle/personal-harness/README.md) 作为 Web 组合包之后的 overlay，拥有个人分类体系、行动手册内容与预算。

不改动核心 agent loop 文件。所有模型可见贡献都通过 `agent/pre-step` 传递，并在推理前成为普通持久用户消息。任务来源记录 `taskId`、匹配信号与回退状态；行动手册来源记录其 `taskId`；召回来源记录 `taskId` 与记忆 id。行动手册明确从属于当前请求和生效策略。记忆文本可能出错、使用标签定界，并且不能授予权限。

## 路由、行动手册与记忆约定

任务评分是确定性的：统计最新一条人类直接消息中不同已配置子字符串信号的数量，选择最高正分，平局按配置顺序解决，只有所有分数均为零时才使用已配置回退任务。每轮次只有一个活跃路由。

Task Router 按平局决胜顺序暴露其不可变分类体系。Task Playbook 配置必须完整覆盖该表；未知、重复与缺失的任务 id 会使加载失败。每份完整渲染行动手册必须在任何 agent 启动前符合已配置 UTF-8 字节预算。行动手册指导执行，但既不授予权限，也不强制工具或操作。

记忆通过 `memory_remember` 显式捕获；每个条目具有全局或任务范围、封闭类别、有界内容和有界检索标签。任务范围由召回使用的同一 Task Router 服务盖章。检索排除其他任务 id，按匹配标签、任务局部性、新鲜度与稳定 id 对合格条目排序，再同时执行条目数量和完整消息字节预算。`memory_forget` 提供幂等删除。

该组合不动态改变工具可见性、不选择可执行工作流，也不自动总结轮次。它们仍是独立决策，因为会引入超出持久上下文选择的强制执行、生命周期与评测要求。

## 验证

包测试固定路由评分与回退、完整行动手册覆盖、持久来源字段、任务记忆隔离、删除、召回排序、字节与捕获限制、组装后的 pre-step 消息、真实 ToolRuntime 注册、Loader 导出形式，以及可解析的个人组合包 patch。无密钥 headless 组合通过真实 Loader 启动，并对 Mock 模型请求前持久化的确切路由与行动手册消息做快照。包 invariant 会为已加载和新追加的会话事件校验带版本路由、行动手册与召回的来源到文本关系。

## 考虑过的替代方案

**把路由、行动手册与记忆放进系统提示词。** 这会失去逐轮次持久来源信息，无法表达存储变更或删除，并让回放依赖配置而非推理期间实际读取的确切上下文。

**把行动手册嵌入 Task Router 定义。** 这会让词法分类拥有执行策略，并迫使每个可复用 Router 消费方携带模型可见指导。独立插件既能要求完整分类覆盖，又允许其他组合在没有行动手册时复用路由。

**用个人状态修改 Agent Loop。** 即使两项行为都适配现有 pre-step、工具与存储扩展点，这仍会削弱包边界，并与上游演进发生冲突。

**立即使用语义路由与向量搜索。** 这会在个人分类体系与记忆纪律尚无证据表明词法路由不足之前，就添加模型或嵌入提供方、非确定性排序、索引生命周期与评测要求。

**不设任务范围、全局存储记忆。** 这更简单，但会让游戏设计决策泄漏进 Harness engineering，并随着无关笔记累积而降低检索质量。

## 后果

个人 fork 获得一条不 fork 执行循环的可观察上下文流水线：路由选择可解释，每类任务获得显式执行指导，记忆持久且可删除，任务范围通过一个服务共享。代价是词法分类器、检入仓库的行动手册维护、显式捕获纪律、一项存储前置条件和额外的逐轮次 token。未来的动态工具路由、自动反思、语义检索、来源信息 UI 与评测必须建立在这些已记录消息之上，而不能绕过它们。
